# Mvy Milestone 3.6 — Leakage-Aware Dataset Splitting\n\nThis stage creates deterministic train/validation/test manifests for the written Mvy corpus.\n\n## Leakage policy\n\nRows are not treated as independent observations. Whole source/document groups are assigned to one split.\n\nGroup identity uses source + document when both exist, document when source is absent, source when document is absent, and a row-specific group when both are absent.\n\nExact normalized transcription duplicates are connected across source/document groups, so the same transcription cannot appear in different splits.\n\nThe release checks leakage-group, source, and document overlap. All must be zero.\n\n## Command\n\npython research/mvy/analysis/milestone-3.6/split_mvy_written_dataset.py --input PATH/TO/written.jsonl --output-dir research/mvy/analysis/milestone-3.6/output\n\nDefault allocation: 80% train, 10% validation, 10% test.\n\n## Outputs\n\n- train.jsonl\n- validation.jsonl\n- test.jsonl\n- group-manifest.jsonl\n- split-summary.json\n- milestone-3.6-split-report.md\n\nEach split record receives split and leakage_group_id fields. Original record content is otherwise preserved.\n\nThis stage deliberately does not perform semantic near-duplicate detection. That is a separate corpus-quality operation.
